## 3. YAMLs e fila

- Treino: `experiments/autoencoder/disc_md_{x1,x1s,x2,x3}_*.yaml` (257).
- SVM: `experiments/autoencoder/disc_md_eval_{x1,x1s,x2,x3}_s*_val_gemttapw.yaml` (11). `family` usa glob, entao 1 YAML cobre todas as familias de um tamanho. So acha estagios terminados, porque o atalho `checkpoints` nasce no fim do treino. `skip: state` deixa relancar depois de cada lote.
- Fila por GPU, uma linha por YAML: `<scratchpad>/s1/queue_gpu{1,2,3,0}.txt`.
- Gerador das grades: `<scratchpad>/d1/plan.py`. Lista de todos: `<scratchpad>/s1/all_yamls.txt`.

Cada GPU e uma fila de 1 run por vez: `gpu_ids` fixo no YAML, `max_per_gpu: 1`, cada braco atras do outro. Assim 640 px e 1 por GPU por construcao, e os 4 slots nunca passam de 4.
640 px so nas GPUs 2 e 3. GPU 1 guarda folga para o SVM; GPU 0 fica para o benchmark.

Ordem em cada fila: X1 (o `p0800_w064` primeiro, que e o ponto oficial e serve de teste de fumaca; dentro do YAML, dataset pequeno primeiro) -> X1s -> X3 -> X2.
X2 e X3 nao dependem de X1, entao nao ha espera entre eles. SVM: `disc_md_eval_x1_*` quando X1 fechar nas 4 filas, depois x1s, x3, x2.

Comando de cada fila (g = 1, 2, 3, 0):
```
cd /dados/home/moliveira/Scalable_Hybrid_FLIM_discovery; export LD_LIBRARY_PATH=/dados/home/moliveira/miniforge3/envs/scalable_FLIM/lib:$LD_LIBRARY_PATH RAY_ACCEL_ENV_VAR_OVERRIDE_ON_ZERO=0; for y in $(cat <scratchpad>/s1/queue_gpu1.txt); do /dados/home/moliveira/miniforge3/envs/scalable_FLIM/bin/python -m experiments.ray.launch $y; done
```
Para rebalancear uma fila: `--gpu-ids` do launcher sobrepoe o YAML.
